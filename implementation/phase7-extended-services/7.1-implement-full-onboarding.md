# Step 7.1: Full Client Onboarding with Contractual Engagement

## Prompt

```
Implement the full client onboarding workflow to include a binding contractual engagement with each new client. Ensure the workflow automatically generates, delivers, and captures electronically signed contracts before provisioning client resources.

Requirements:
1. Extend CreateClientOnboardingWorkflow to insert contract request and signature steps.
2. Publish a `client.contract_requested` event and await a `client.contract_signed` event before proceeding.
3. Integrate a contract generation service that merges client context into a parameterized contract template.
4. Integrate an electronic signature provider and programmatically capture signed agreements.
5. Implement contract versioning, secure storage, and tamper-evident audit trails.
6. Update event bus handlers and workflow step handlers to support contract-related events.
7. Update documentation and integration guides to reflect the contractual onboarding flow.

Output should include implementation code, updated workflow definitions, contract templates, handler wiring, and documentation updates.
```

## Implementation Guidelines

### Workflow Extension

#### Step Insertion
- Modify `CreateClientOnboardingWorkflow` in `pkg/events/workflows.go` to insert a new step for contract request between client validation and profile setup.
- Define a `StepTypeEvent` for `client.contract_requested` and a `StepTypeWait` for `client.contract_signed` with appropriate timeout and retry settings.

#### Event Bus Integration
- Publish the `client.contract_requested` event via the service event bus when the contract request step executes.
- Ensure the workflow engine waits for the `client.contract_signed` event before advancing to `setup-profile`.

### Contract Generation & Signature

#### Template Design
- Create a parameterized contract template in the `contracts/` directory using Go text/template or a similar templating engine.
- Define placeholders for client name, project scope, fees, dates, and legal terms.

#### Generation Service
- Implement a contract generation service in the legal/compliance module that renders the template with workflow context and returns a PDF or signing link.

#### Electronic Signature Handler
- Integrate with an electronic signature provider (e.g., DocuSign, HelloSign) via API to send contracts and capture signed documents.
- Emit a `client.contract_signed` event upon successful signature capture, including signature metadata.

#### Audit Trail & Storage
- Store each signed contract version in a secure, tamper-evident store (e.g., S3 or database blob) with a timestamp and hash.
- Record audit metadata (signer identity, IP, timestamp) for compliance and dispute resolution.

### Workflow Engine Changes

#### Step Handler Registration
- Register a new or reuse an existing `StepHandler` in `WorkflowEngine` for handling contract signature wait steps.
- Update `stepHandlers` initialization in `pkg/events/workflows.go` to include the contract wait handler.

### Documentation & Integration Guides

#### Legal Framework Update
- Update `docs/LegalFramework.md` to document the new contractual onboarding workflow, events, and audit requirements.

#### Service Orchestration Update
- Add a section in `docs/ServiceOrchestration.md` under "Workflow Orchestration" showing the extended onboarding sequence with contract steps.

#### Implementation README
- Create a README in `implementation/phase7-extended-services` listing the full onboarding with contractual engagement component.
